`effect-api-query` turns your Effect RPC group or HttpApi definition into typed query options,
mutation options, and cache keys. Pass them directly to TanStack Query while your application
controls its client, cache policies, and resource lifetime.

## What it provides

- Typed keys and options for reads, mutations, pagination and conditional queries.
- Accumulated and live RPC/SSE views, buffered HTTP metadata and multipart mutations.
- Decoded query data and execution failures preserving the complete Effect Cause.

See [Feature Support](/effect-api-query/getting-started/feature-support/) for operation boundaries.

## Choose a path

- Start with an existing contract and ready client: [RPC quick start](/effect-api-query/getting-started/quick-start/)
  or [HTTP quick start](/effect-api-query/getting-started/http-quick-start/).
- Consume options in [React](/effect-api-query/guides/react-query/), [Vue](/effect-api-query/guides/vue-query/),
  [Solid](/effect-api-query/guides/solid-query/), [Svelte](/effect-api-query/guides/svelte-query/),
  [Angular](/effect-api-query/guides/angular-query/), or [TanStack Start](/effect-api-query/guides/tanstack-start/).
- [Run the examples](/effect-api-query/examples/) for complete Vite React and Start applications.
- Look up [API contracts](/effect-api-query/reference/public-exports/) and
  [compatibility limits](/effect-api-query/reference/compatibility-and-limits/).
