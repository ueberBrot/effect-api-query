`effect-api-query` combines an Effect declaration, a ready client, and your cache prefix into a
typed utility tree. Its leaves build options for native TanStack Query consumers: buffered reads,
mutations, pages, RPC streams, HTTP SSE, and buffered HTTP metadata.

## Learn the library contract

| Goal                                       | Read                                                                                                                                                                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Understand generated branches and leaves   | [Generated Utility Model](/effect-api-query/concepts/queries-and-mutations/)                                                                                                                                 |
| Supply input and interpret decoded data    | [Inputs and Query Data](/effect-api-query/concepts/data-normalization/)                                                                                                                                      |
| Choose a cached representation             | [Queries](/effect-api-query/guides/queries/), [Pagination](/effect-api-query/guides/pagination/), [Streaming](/effect-api-query/guides/streaming/), [HTTP Metadata](/effect-api-query/guides/http-metadata/) |
| Target reads and writes in the cache       | [Cache Keys and Filters](/effect-api-query/guides/cache-filters/)                                                                                                                                            |
| Share typed retries and mutation callbacks | [Defaults and Policies](/effect-api-query/guides/query-defaults/)                                                                                                                                            |
| Reuse contract types in application code   | [Type Inference](/effect-api-query/reference/type-inference/)                                                                                                                                                |
| Inspect failures and release resources     | [Handle Failures](/effect-api-query/guides/handle-failures/), [Client Lifecycle](/effect-api-query/concepts/client-lifecycle/)                                                                               |

The library owns generated keys, functions, cache-view identity, and adaptation of Effect failures.
TanStack owns the cache and its native consumers. Your application owns its ready client,
transport, authentication, providers, runtime, and resource lifetime.

## Connect your application

Use the generated options with your existing native integration:

- [React Query](/effect-api-query/guides/react-query/) includes a complete client/provider setup and
  links [Suspense recovery](/effect-api-query/guides/suspense-and-recovery/).
- [Vue](/effect-api-query/guides/vue-query/), [Solid](/effect-api-query/guides/solid-query/),
  [Svelte](/effect-api-query/guides/svelte-query/), and [Angular](/effect-api-query/guides/angular-query/)
  explain each wrapper's reactive options and typing constraints.
- [Router and Start](/effect-api-query/guides/tanstack-start/) covers loaders, request ownership,
  and server rendering. [Hydration](/effect-api-query/guides/hydrate-unary-data/) and
  [Stream Snapshots](/effect-api-query/guides/stream-snapshots/) preserve decoded cache data.

The [integration overview](/effect-api-query/integrations/) explains the shared provider,
reactivity, and client-lifetime boundaries. [Run the examples](/effect-api-query/examples/) for
complete Vite React and TanStack Start applications.

Use [API Reference](/effect-api-query/reference/public-exports/) for exported values and types,
and [Compatibility and Limits](/effect-api-query/reference/compatibility-and-limits/) for the
tested dependency contracts and runtime limits.
