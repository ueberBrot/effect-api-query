`effect-api-query` turns your Effect RPC group or HttpApi definition into typed query options,
mutation options, and cache keys. Pass them directly to TanStack Query while your application
controls its client, cache policies, and resource lifetime.

## What it provides

- Queries and mutations for unary RPCs and buffered HTTP endpoints.
- Infinite and conditional queries for both adapters.
- Accumulated streams and live queries for RPCs.
- Semantic cache keys for prefetching, cache updates, and invalidation.
- Typed execution failures that retain the complete Effect Cause.

## Choose a path

- Create utilities and run a query with the [RPC quick start](/effect-api-query/getting-started/quick-start/)
  or [HTTP quick start](/effect-api-query/getting-started/http-quick-start/).
- [Run the examples](/effect-api-query/examples/) to compare standalone Vite hosting with
  TanStack Start routes for both protocols.
- Check [feature support](/effect-api-query/getting-started/feature-support/) to choose operations
  and plan your integration.
- Use the [React Query guide](/effect-api-query/guides/react-query/) for hooks and mutations.
- Use the [TanStack Start guide](/effect-api-query/guides/tanstack-start/) for loaders, SSR, and
  hydration.
- Read [compatibility and limits](/effect-api-query/reference/compatibility-and-limits/) before
  adopting the package.
