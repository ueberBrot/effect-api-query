# Derive hydration codecs from Effect contracts and compose registries

Status: Accepted.

## Context

Manual hydration registration through `queryViewCodec`, `infiniteQueryCodec`, and `createHydrationRegistry` requires applications to construct a live utility tree and register every leaf and view by hand, including `HttpApiSchema.WithHeaders` wrappers, ADR 0012 `undefined -> null` adapters, and `streamed` `undefined` markers. Effect `4.1.4` exposes `RpcGroup` request schemas and `HttpApi` endpoint success schemas directly on the contract without requiring a client.

## Decision

1. **Contract-derived hydration registry:** Add an overloaded `createContractHydrationRegistry(contract, options?)` accepting an `RpcGroup` or `HttpApi` directly with no live client and an optional non-empty `keyPrefix` defaulting to `readonly []`. Auto-derive `"query"` for unary RPCs and buffered queryable HTTP endpoints, `"metadata"` for buffered queryable HTTP endpoints, and `"live"` and `"streamed"` for streaming RPCs and HTTP `StreamSse` / `StreamNdjson` endpoints. Skip multipart-only and unsupported HTTP endpoints (`StreamUint8Array`, `Upgrade`, and streaming payloads).
2. **Global `views` and flat dot-path `paths`:** Support a strict top-level `views` boolean map (`{ query?, metadata?, live?, streamed? }`, omitting `metadata` for RPC) and a flat dot-path `paths` map supporting `{ infinite: { pageParam, page? } }`, type-checked per-view codec overrides, and whole-path or per-view `false` opt-outs. Inherit a custom `paths[path].query` codec as the default `data` codec for `metadata` and `page` codec for `infinite` unless overridden or disabled.
3. **Lossless Effect `4.1.4` derivation and cache invariants:** Derive JSON codecs via `Schema.toCodecJson` across `Json`, `Text`, `FormUrlEncoded`, `Uint8Array`, and `disableCodecs: true`, inspecting `endpoint.success` directly and `RpcSchema.isStreamSchema(rpc.successSchema)`. Compose `WithHeaders` via `{ body, headers }` and `HttpApiSchema.withHeaders` for buffered and per-chunk streaming views, multi-success unions via `Schema.Union`, and `encodeToWithHeaders` via `Schema.toCodecJson(Schema.toType(schema))`. Adapt `query`, `metadata` (`.data`), `infinite` (`.pages[i]`), and `live` views for [ADR 0012](0012-normalize-undefined-query-success-to-null.md) (`undefined -> null` while keeping `WithHeaders` wrappers with `undefined` body intact), tag `undefined` elements distinctly from `null` in `streamed` arrays, and freeze decoded HTTP metadata envelopes and raw header maps.
4. **Eager AST validation and unified `HydrationCodecError`:** Inspect derived encoded ASTs eagerly at construction time and throw `HydrationCodecError` (`DuplicateCodec | UnknownQuery | UnsettledQuery | InvalidKeyPrefix | InvalidContractPath | UnknownPath | UnencodableSchema`, with optional `path` and `view`) for opaque `Schema.declare`, `Redacted`, or unencodable `encodeToWithHeaders` schemas unless overridden or opted out with `false`.
5. **Composable `createHydrationRegistry`:** Retain `createHydrationRegistry`, `queryViewCodec`, `infiniteQueryCodec`, and `hydrationCallbacks` as low-level primitives. Track package-created `HydrationRegistry` instances via an internal `WeakMap` so `createHydrationRegistry` flattens mixed `HydrationCodec` and `HydrationRegistry` entries with strict `DuplicateCodec` detection, longest-prefix selection, exact service unions, and explicit `HydrationCodecError` rejection of non-package structural registries.

## Consequences

Applications hydrate rich Effect RPC and HTTP contracts without a live client or repetitive view registration, while preserving escape hatches for custom overrides, `infinite` page parameters, and multi-contract registry composition. Contract-derived types scale linearly (`O(N)`) via bare fast paths, split unmodified-vs-overridden RPC services, per-group HTTP endpoint exclusion, `Schema.Constraint` stream extraction, and optional-property fallback service unions.
